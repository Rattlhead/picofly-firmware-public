# Инструкция мастеру: PicoFly FlashDiag

> FlashDiag 3.01/3.02 — экспериментальные диагностические прошивки для flash BY25Q20AW. Это **не** обычное обновление PicoFly. Console update и rollback для этой flash запрещены: прошивка и восстановление выполняются только вашим привычным способом через USB/BOOTSEL.

## Что подготовить

1. Выберите **одну** прошивку для серии:
   - `PicoFly-FlashDiag-3.01-base-2.74` — диагностическая копия версии 2.74;
   - `PicoFly-FlashDiag-3.02-base-2.80` — диагностическая копия версии 2.80.
2. Для первой или чистой установки через BOOTSEL берите файл с окончанием `-clean-install.uf2` из папки выбранной версии. Он содержит single-slot bootloader и FlashDiag.
3. `update.bin` остаётся отдельным образом обновления, но для BY25Q20AW его нельзя применять штатным console updater: обычный двухслотовый путь на этой flash не существует. Используйте его только если разработчик отдельно дал совместимый USB-инструмент и инструкцию.
4. Получите программу выгрузки для своего компьютера и распакуйте ZIP в обычную доступную папку, например на Рабочий стол:
   - Windows 10/11 x64: `FlashDiag Exporter-Windows-x64.zip`;
   - macOS 12 или новее: `FlashDiag Exporter-macOS-universal2.zip`.
5. Нужен USB-кабель с передачей данных и доступ к кнопке `BOOT` на PicoFly.
6. До первого запуска подпишите для себя плату: `тонкий` или `толстый` текстолит. Программа не угадывает этот признак сама.

Python, `picotool`, драйверы Python и дополнительные библиотеки устанавливать не нужно: всё нужное находится внутри программы выгрузки.

## Одна диагностическая серия

Одна серия — это **одна плата + одна версия FlashDiag + три запуска консоли**. Не смешивайте 3.01 и 3.02 в одном журнале.

1. Для чистой установки: удерживайте `BOOT`, подключите PicoFly по USB, дождитесь диска BOOTSEL и скопируйте на него выбранный `clean-install.uf2`. Дождитесь, пока диск отключится сам, затем отсоедините USB.
2. `clean-install.uf2` заменяет область bootloader/config/fuse `0x00000..0x0FFFF` и устанавливает FlashDiag в `0x10000..0x27FFF`; диагностический журнал `0x28000..0x3FFFF` он не записывает. Храните привычный recovery-файл до завершения эксперимента.
3. Запустите консоль. Дождитесь загрузки либо устойчивого повторяющегося кода ошибки.
4. Полностью выключите питание консоли.
5. Повторите пункты 3--4 ещё два раза. Всего должно быть три запуска.
6. После третьего запуска оставьте консоль выключенной.
7. Удерживайте `BOOT` на PicoFly, подключите USB-кабель к компьютеру и отпустите `BOOT`. PicoFly должен появиться как устройство BOOTSEL.
8. Запустите FlashDiag Exporter, как описано ниже.
9. В меню сначала выберите `1 — Проверить подключение PicoFly`. Если устройство найдено — выберите `2 — Выгрузить диагностический журнал`.
10. Дождитесь сообщения `Отчёт сохранён: ...`. Не отключайте USB во время чтения или очистки.

При полном и проверенном журнале программа сначала сохраняет все файлы отчёта, а затем автоматически очищает **только** 96 KiB область FlashDiag. Если журнал неполный, повреждён или возникла ошибка записи на компьютер, ничего автоматически не стирается.

## Как запустить программу выгрузки

### Windows 10/11 x64

1. Распакуйте `FlashDiag Exporter-Windows-x64.zip`.
2. Откройте распакованную папку в Проводнике, щёлкните по адресной строке, введите `cmd` и нажмите Enter.
3. В чёрном окне введите:

```text
"FlashDiag Exporter.exe"
```

Если открыли PowerShell, используйте:

```text
& ".\FlashDiag Exporter.exe"
```

Если SmartScreen спрашивает разрешение, сначала убедитесь, что ZIP получен от ответственного разработчика и его SHA-256 совпадает с предоставленной контрольной суммой; затем можно выбрать «Подробнее» → «Выполнить в любом случае».

#### Однократная настройка WinUSB

Диск `RPI-RP2` подтверждает BOOTSEL, но сам по себе не даёт `picotool` доступ к интерфейсу чтения. До первой выгрузки на данном компьютере:

1. Удерживая `BOOT`, подключите PicoFly по USB и отпустите кнопку; убедитесь, что появился диск `RPI-RP2`.
2. Скачайте [Zadig с официального сайта](https://zadig.akeo.ie/). Это один исполняемый файл, обычная установка программы не требуется.
3. Запустите Zadig от имени администратора, включите `Options` → `List All Devices`.
4. Выберите только `RP2 Boot (Interface 1)`, назначьте справа `WinUSB`, нажмите `Install Driver` или `Replace Driver`.
5. Не меняйте `Interface 0` и драйвер диска `RPI-RP2`. Если `RP2 Boot (Interface 1)` не показан, отмените действие и снова войдите в BOOTSEL.
6. В Exporter выберите `1 — Проверить подключение PicoFly`, а после успешного обнаружения — `2 — Выгрузить диагностический журнал`.

Требование WinUSB для `picotool` на Windows описано в [официальной инструкции Raspberry Pi](https://github.com/raspberrypi/picotool#zadig). После установки WinUSB диск `RPI-RP2` должен остаться доступен.

### macOS 12+

1. Распакуйте `FlashDiag Exporter-macOS-universal2.zip`.
2. Откройте Terminal.
3. Введите `cd `, затем перетащите распакованную папку в окно Terminal и нажмите Enter.
4. Введите:

```text
./FlashDiag\ Exporter
```

Если macOS впервые блокирует запуск, нажмите Control-клик по `FlashDiag Exporter` в Finder и выберите «Открыть». Разрешайте запуск только пакета, полученного от ответственного разработчика.

После старта программа показывает полный путь папки `FlashDiag_Reports`. Туда будут записаны результаты; по умолчанию она находится рядом с самой программой.

## Что отправить разработчику

После успешной выгрузки откройте `FlashDiag_Reports`. Внутри будет каталог вида:

```text
FlashDiag_3.01_base-2.74_<ID-платы>_<дата-время>
```

Добавьте к имени **копии** этой папки признак текстолита, например:

```text
тонкий__FlashDiag_3.01_base-2.74_...
```

Заархивируйте и отправьте весь каталог целиком. В нём обязательно должны быть пять файлов:

- `summary.md` — краткий отчёт;
- `cycles.csv` — все сохранённые glitch-циклы;
- `journal-raw.bin` — исходные 96 KiB журнала;
- `trace-raw.bin` — цифровые трассы;
- `metadata.json` — версии, адреса и контрольные суммы.

Не переименовывайте и не редактируйте эти пять файлов по отдельности.

Для сравнения нужны четыре отдельных каталога: тонкий 3.01, тонкий 3.02, толстый 3.01 и толстый 3.02.

## Если что-то пошло не так

| Сообщение | Что делать | Стирается ли журнал |
| --- | --- | --- |
| `NO_DEVICE` | Отключите USB, удерживайте `BOOT`, подключите USB снова. Если `RPI-RP2` виден в Проводнике, выполните однократную настройку WinUSB для `RP2 Boot (Interface 1)` выше, затем в меню выберите пункт 1. | Нет |
| `MULTIPLE_DEVICES` | Отключите остальные RP2040/платы от компьютера. | Нет |
| `READ_FAILED` | Не очищайте память. Повторите выгрузку на том же или другом поддерживаемом компьютере. | Нет |
| `OUTPUT_FAILED` | Убедитесь, что папка `FlashDiag_Reports` доступна для записи и на диске есть место; повторите выгрузку. | Нет |
| `LOG_INVALID` | Сохраните полученные raw-файлы, не очищайте журнал; проверьте, что прошита именно FlashDiag 3.01/3.02. | Нет |
| `CLEAR_FAILED` | Отчёт уже сохранён по указанному пути. При необходимости повторите только очистку. | Не гарантируется |

Пункт `3 — Очистить журнал вручную` используйте только когда решили отказаться от невыгруженных данных. Он показывает найденную плату и диапазон `0x10028000..0x1003FFFF`, а затем требует точного ввода `ДА`.

Цифровая трасса показывает, на каком этапе и на какой из линий `RST`, `CLK`, `CMD`, `DATA0` появилась нестабильность. Она не измеряет аналоговую амплитуду шума: для окончательного подтверждения подозрительной линии нужен осциллограф.
