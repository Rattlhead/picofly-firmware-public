# PicoFly: памятка мастеру по лабораторным прошивкам

Этот документ помогает выбрать правильную ветку прошивки и безопасно собрать данные для разработчика. В репозитории есть две независимые линии:

| Если нужно | Используйте | Результат |
| --- | --- | --- |
| Проверить обычный запуск и получить расширенную LED-диагностику | **2.81+ Data0Lab** | Версия, результат запусков и LED-ритм |
| Записать подробные данные о сбое для анализа | **3.x FlashDiag** | Выгруженный диагностический журнал и отчёт |

Не смешивайте эти линии в одной серии: FlashDiag 3.01/3.02 — диагностическая прошивка, а не очередная версия Data0Lab 2.81+.

## Перед началом

- Используйте USB-кабель с передачей данных и имейте под рукой привычный recovery-файл.
- Подпишите плату как `тонкий` или `толстый` текстолит до начала серии. По внешнему виду программа это не определяет.
- На чипе BY25Q20AW (256 KiB) **не используйте** штатные console update и rollback: второй слот обновления не помещается во flash. Установка и восстановление — только через USB/BOOTSEL.
- Не прошивайте версии со статусом `blocked-by-measurement`: они не предназначены для полевой проверки.

## Выбор ветки

### 2.81+ Data0Lab: когда нужен обычный тест

Выбирайте эту ветку, если требуется проверить поведение платы при обычном запуске и записать LED-диагностику. Для первой серии разрешены только 2.81, 2.82 и 2.83:

| Версия | Назначение |
| --- | --- |
| 2.81 | Алгоритм 2.80 с расширенной LED-диагностикой |
| 2.82 | Фильтр и гистерезис DAT0 |
| 2.83 | Очистка и перезапуск состояний PIO между попытками |
| 2.99 | Отдельная максимальная LED-диагностика DAT0/CLK/PIO без журнала |

1. Возьмите `clean-install` UF2 выбранной версии для установки через USB/BOOTSEL.
2. Прошейте только через BOOTSEL и выполните указанную серию холодных запусков.
3. Для каждого запуска зафиксируйте версию, CRC, результат, время, LED-ритм и факт восстановления через USB/BOOTSEL.
4. В 2.81–2.83 запишите фиолетовую категорию и красную причину. В 2.99 дополнительно запишите четыре синих бита контекста после второй паузы 1,5 с. На одноцветном Pico особенно важны порядок полей, число импульсов и паузы.

Подробный порядок серии и полный контракт профилей: [Инструкция для тестировщика Data0Lab](tester-guide-ru.md). Этот файл сгенерирован из реестра профилей; вручную в него ничего не добавляйте.

Полная расшифровка двухполевых кодов 2.81–2.83 и трёхполевых кодов 2.99: [Коды расширенной LED-диагностики 2.81+](led-error-codes-2.81-plus-ru.md).

### 3.x FlashDiag: когда разработчику нужен журнал с чипа

Выбирайте FlashDiag только для диагностической серии. Она сохраняет данные о попытках запуска во flash-журнал, чтобы затем прочитать их с платы через USB/BOOTSEL.

| Версия | Базовая прошивка | Когда выбирать |
| --- | --- | --- |
| 3.01 | 2.74 | Нужна диагностика поведения базы 2.74 |
| 3.02 | 2.80 | Нужна диагностика поведения базы 2.80 |

1. Выберите **одну** версию FlashDiag на всю серию; не смешивайте 3.01 и 3.02 в одном журнале.
2. Удерживайте `BOOT`, подключите плату по USB и скопируйте на диск BOOTSEL соответствующий `-clean-install.uf2`.
3. Отсоедините USB, выполните три запуска консоли с полным отключением питания между ними.
4. После третьего запуска оставьте консоль выключенной.
5. Снова войдите в BOOTSEL: удерживайте `BOOT`, подключите USB к компьютеру, затем отпустите кнопку.
6. Запустите программу чтения журнала и сначала проверьте подключение, затем выгрузите журнал.

`update.bin` FlashDiag не применяйте штатным console updater на BY25Q20AW. Для этой памяти это небезопасный и неподдерживаемый путь.

## Программа чтения журнала FlashDiag

Мастеру выдаётся готовая программа **FlashDiag Exporter**: Python и отдельный `picotool` устанавливать не нужно. Для первого чтения PicoFly на Windows требуется однократно настроить системный USB-драйвер WinUSB — порядок приведён ниже.

### Готовая программа для мастера

1. Распакуйте пакет для своей ОС:
   - Windows 10/11 x64 — `FlashDiag Exporter-Windows-x64.zip`;
   - macOS 12+ — `FlashDiag Exporter-macOS-universal2.zip`.
2. Запустите программу из распакованной папки:

   **Windows, cmd**

   ```text
   "FlashDiag Exporter.exe"
   ```

   **Windows, PowerShell**

   ```text
   & ".\FlashDiag Exporter.exe"
   ```

   **macOS, Terminal**

   ```text
   ./FlashDiag\ Exporter
   ```

3. В меню выберите `1 — Проверить подключение PicoFly`. При найденной единственной плате выберите `2 — Выгрузить диагностический журнал`.
4. Дождитесь сообщения `Отчёт сохранён: …` и не отключайте USB до завершения операции.

### Windows: однократная настройка доступа к PicoFly

Диск `RPI-RP2` в Проводнике подтверждает, что PicoFly вошёл в BOOTSEL и USB-кабель передаёт данные. Но для чтения журнала `picotool` также нужен драйвер **WinUSB** на отдельном USB-интерфейсе RP2040.

1. Введите PicoFly в BOOTSEL: удерживайте `BOOT`, подключите USB, затем отпустите кнопку. Убедитесь, что появился диск `RPI-RP2`.
2. Скачайте один исполняемый файл [Zadig с официального сайта](https://zadig.akeo.ie/) и запустите его от имени администратора. Его не нужно устанавливать как обычную программу.
3. В Zadig откройте `Options` → `List All Devices`, выберите строго `RP2 Boot (Interface 1)`, справа выберите `WinUSB`, затем нажмите `Install Driver` (либо `Replace Driver`, если кнопка названа так).
4. **Не выбирайте `Interface 0` и не меняйте драйвер диска `RPI-RP2`**. Если строки `RP2 Boot (Interface 1)` нет, ничего не устанавливайте: повторно войдите в BOOTSEL и проверьте список устройств.
5. Вернитесь в FlashDiag Exporter, выберите `1 — Проверить подключение PicoFly`, затем `2 — Выгрузить диагностический журнал`.

Это требование и точное имя интерфейса подтверждены [документацией Raspberry Pi для picotool](https://github.com/raspberrypi/picotool#zadig). После успешной настройки `RPI-RP2` остаётся доступен в Проводнике.

При полном и проверенном журнале Exporter сохраняет отчёт, затем автоматически очищает только 96 KiB область FlashDiag и проверяет очистку. Если журнал повреждён, неполный или отчёт не удалось записать на компьютер, данные не стираются.

Не запускайте ручную очистку журнала, пока не сохранён и не проверен полный отчёт. Пункт `3 — Очистить журнал вручную` предназначен только для осознанного отказа от невыгруженных данных и требует подтверждения `ДА`.

## Что передать разработчику

После успешной выгрузки откройте `FlashDiag_Reports` рядом с программой. В нём будет каталог серии. Добавьте к имени **копии** каталога признак текстолита, например `тонкий__FlashDiag_3.02_base-2.80_…`, затем отправьте архив всего каталога.

Не переименовывайте и не редактируйте файлы внутри. В отчёте должны остаться:

- `summary.md`;
- `cycles.csv`;
- `journal-raw.bin`;
- `trace-raw.bin`;
- `metadata.json`.

Для сравнения плат и баз нужны отдельные серии: тонкий 3.01, тонкий 3.02, толстый 3.01 и толстый 3.02.

## Если чтение не удалось

| Сообщение | Действие |
| --- | --- |
| `NO_DEVICE` | Повторно войдите в BOOTSEL. Если диск `RPI-RP2` уже виден в Windows, выполните однократную настройку WinUSB для `RP2 Boot (Interface 1)` выше, затем снова выберите проверку подключения. |
| `MULTIPLE_DEVICES` | Отключите другие RP2040-устройства и повторите проверку. |
| `READ_FAILED` | Не очищайте журнал; повторите выгрузку на том же или другом поддерживаемом компьютере. |
| `OUTPUT_FAILED` | Проверьте доступ на запись и место в папке `FlashDiag_Reports`; повторите выгрузку. |
| `LOG_INVALID` | Сохраните raw-файлы, не очищайте журнал и проверьте, что установлена FlashDiag 3.01/3.02. |
| `CLEAR_FAILED` | Отчёт уже сохранён; при необходимости повторите только очистку. |

Полные шаги установки, состав отчёта и дополнительные пояснения: [Инструкция мастеру: PicoFly FlashDiag](flashdiag-tester-guide-ru.md). Сведения о выпуске и контрольных суммах пакетов: [Ведомость сборки FlashDiag](flashdiag-build-ledger.md).
